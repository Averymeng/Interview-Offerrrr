大语言模型（LLM）核心概念
以下知识体系是面试的通用基础，建议你系统梳理并内化为自己的表达。
关键术语与原理
预训练（Pre-training）与微调（Fine-tuning）：预训练是在海量语料上学习通用语言表示，微调是在特定任务数据上调整模型参数。理解这一区别有助于你判断哪些场景需要微调、哪些场景用Prompt Engineering即可。
上下文窗口（Context Window）：模型一次能处理的token数量限制。当前主流模型如GPT-4o支持128K，Claude 3.5支持200K。设计Agent时要考虑信息如何分片、记忆如何管理。
幻觉（Hallucination）——检测、兜底与纠正机制
幻觉指模型生成看似合理但实际错误的内容，是AI产品落地的头号风险。AI产品设计必须从系统层面建立三层防御机制：
第一层：检测机制。在产品上线前建立多维度的幻觉识别能力。常见方法包括：事实核查（将模型输出与可靠知识库或搜索结果交叉比对，标记不一致之处）、置信度评估（利用模型自身的logits或额外训练的判别器，对输出声明给出可信度评分）、一致性检验（对同一问题用不同方式提问或让多个独立模型回答，对比结果一致性，不一致则标记为高风险）、规则拦截（针对已知高风险领域如数值计算、时间日期、专有名词，设置正则或规则引擎进行硬校验）。
第二层：兜底机制。当检测到幻觉风险或模型输出置信度低于阈值时，系统必须优雅降级而非直接输出。兜底策略包括：转人工接管（在客服、医疗、法律等高风险场景，自动将对话转接人工，并附带模型已生成的草稿供参考）、输出降级（关闭创造性生成，仅返回从知识库中检索到的原文片段，牺牲体验换取准确性）、多轮确认（对关键信息要求用户二次确认，例如「您询问的截止日期是2025年3月15日，请问是否确认？」）、信息分层展示（将高置信度和低置信度内容区分展示，低置信度内容标注「仅供参考，请核实」）。
第三层：纠正机制。幻觉不可能100%杜绝，因此需要建立发现后的快速纠正闭环。具体做法包括：用户反馈通道（在界面显著位置提供「内容有误」举报按钮，并设计简单的分类标签如「事实错误」「过时信息」「理解偏差」）、案例回流（将已确认的幻觉案例按错误类型、领域、模型版本等维度结构化入库，定期用于模型迭代或Prompt优化）、主动修正（对已发现错误的公开输出，在展示页面添加勘误声明，并触发模型对新请求避免重复同样错误）、红队测试（定期组织内部或外部团队对系统进行对抗性测试，专门诱导模型产生幻觉，暴露盲点）。
总结来说，好的幻觉治理不是「让模型不出错」，而是「让系统能在出错时被及时发现、优雅处理、快速修复」，并将每一次错误转化为系统进化的数据燃料。
RAG（Retrieval-Augmented Generation）：检索增强生成，通过外挂知识库让模型回答基于事实。你的Agent项目中的「案例召回机制」本质上就是一种RAG应用，面试时可主动关联。
RAG——检索增强生成
RAG的核心思想是：不依赖模型参数中存储的静态知识，而是在每次生成前先从外部知识库中检索相关信息，将检索结果作为上下文输入给模型，引导其基于事实作答。这相当于给大模型配了一个「实时资料库」。
一个典型的RAG流程分为四步：
索引（Indexing）：将企业或领域的文档、数据库、网页等内容进行分块（Chunking），并用Embedding模型转化为向量，存入向量数据库（如Milvus、Pinecone、Weaviate）。
检索（Retrieval）：用户提问时，先将问题也转化为向量，在向量数据库中搜索最相似的文档块（Top-K召回）。
增强（Augmentation）：将检索到的文本片段与用户原始问题拼接成新的Prompt，明确指示模型「请基于以下参考资料回答」。
生成（Generation）：模型在受限上下文内生成回答，大幅降低凭空捏造的概率。
RAG的优势在于：知识可实时更新（无需重新训练模型）、回答可溯源（能指出信息来自哪篇文档）、部署成本远低于微调。局限性在于：检索质量直接决定生成质量（如果召回的文档不相关，模型会被误导）、对复杂多跳推理（需要跨文档关联信息）支持有限。你的复盘诊断Agent中「归一化签名+SQL匹配召回相似案例」的设计，本质上就是RAG的变体——用结构化签名替代Embedding检索，用SQL精确匹配替代向量相似度搜索。
Prompt Engineering核心技巧
Prompt Engineering是通过优化输入指令来提升模型输出质量的技术，不需要改动模型参数，是产品经理最常用、最应精通的AI调优手段。以下是面试中应熟练运用的核心技巧：
Zero-shot与Few-shot：Zero-shot指直接给任务指令，不附示例，适合模型能力已经很强的通用任务。Few-shot则在指令后附上2-5个输入-输出示例，让模型「模仿」期望的格式和风格。Few-shot在格式控制、风格迁移、特定领域术语使用上效果显著，是产品化Prompt的标配。
Chain-of-Thought（CoT，思维链）：在Prompt中明确要求模型「一步步思考」或「先分析再给出结论」，引导模型展示推理过程而非直接跳答。CoT能显著提升模型在数学、逻辑、复杂分析任务上的准确率，因为它强迫模型把隐性推理显性化。进阶版本是Few-shot-CoT，即在示例中不仅展示最终答案，还展示完整的中间推理步骤，让模型学习「如何思考」。
ReAct（Reasoning + Acting）：让模型交替进行「思考（Thought）」和「行动（Action）」。Thought阶段分析当前状态和下一步该做什么，Action阶段调用工具（如搜索、计算器、数据库查询）获取外部信息，然后基于Observation继续Thought。这种循环让模型能够处理需要多步交互的复杂任务，是Agent设计的经典Prompt模式。
结构化输出（JSON Mode / Function Calling）：强制模型按指定格式（如JSON、Markdown表格）输出，便于下游系统解析。现代模型如GPT-4、Claude都支持JSON mode，通过在Prompt中定义清晰的字段名、类型和示例，可以稳定获得结构化数据，避免解析失败。Function Calling则更进一步，让模型自主判断是否需要调用预定义工具、传什么参数，是构建Agent的核心能力。
角色设定（Role Prompting）：在Prompt开头为模型设定一个专业角色，如「你是一位资深游戏美术总监，擅长将概念需求转化为详细的角色设计文档」。角色设定能激活模型在预训练时学到的领域知识，提升输出专业度和一致性。
约束与边界（Constraint Prompting）：明确告诉模型「不要做什么」和「必须做什么」。例如「回答不超过200字」「不要提及竞争对手品牌」「如果信息不确定，请明确说『我不确定』」。约束越清晰，输出越可控。
模型能力边界认知
面试中很可能被问到「你认为当前大模型有哪些能力边界」，以下是关键要点：
数学与逻辑推理：复杂多步推理仍易出错，需要设计验证和反思机制。
实时信息获取：模型知识有截止日期，需通过工具调用（Tool Use）或RAG补充。
精确控制与一致性：相同Prompt多次运行结果可能不同，对确定性要求高的场景需要设置temperature=0或增加约束层。
长文本理解与精准定位：长文档中关键信息提取的准确率下降，需要分段处理或设计索引机制。
多模态理解：图像理解已较成熟，但视频时序理解、3D空间推理仍在快速发展中。
Agent设计框架
腾讯IEG和智珑创新的岗位都高度强调Agent能力，以下是必须掌握的知识体系：
ReAct 框架
ReAct = Reasoning（推理）+ Acting（行动）。Agent先进行思考（Thought），决定下一步行动（Action），观察结果（Observation），然后继续推理。这种循环让Agent能够处理复杂多步任务。你的复盘诊断Agent本质上就是ReAct的变体：先诊断数据（Thought），再决定调用哪个分析模块（Action），观察输出后继续下一步。
Tool Use / Function Calling
让LLM调用外部工具（如搜索、数据库、计算器、代码执行器）来扩展能力。产品设计中需要考虑：工具注册与描述（让模型理解每个工具的作用）、参数校验（防止错误调用）、错误处理（调用失败时如何降级）、权限控制（哪些用户/场景可以使用哪些工具）。
多Agent协作架构
复杂系统（如游戏资产生成平台）往往需要多个Agent协作：一个负责需求理解、一个负责风格迁移、一个负责质量审核。关键设计要点包括：Agent间通信协议、任务分配与调度、冲突解决机制、全局状态管理。可以类比你Agent项目中的「规则计算+LLM推理」混合架构来理解。
Agent评测维度
你的腾讯JD明确要求「搭建AI生成质量评测体系」，你的Agent项目也建立了评测机制。系统化的Agent评测应覆盖：任务完成率（是否达成目标）、步骤合理性（中间步骤是否合乎逻辑）、工具调用准确率、响应时间、用户体验（交互自然度）、安全性与合规性。
多模态与3D生成技术基础
这是腾讯IEG面试的重点，你需要建立基础认知：
文生图技术
文生图（Text-to-Image）是生成式AI在视觉领域最先成熟、也是商业化最广泛的能力。理解其技术原理和产品层面的关键概念，是面试中展示技术敏感度的核心素材。
Diffusion模型——文生图的主流架构
当前几乎所有主流文生图工具（Stable Diffusion、Midjourney、DALL-E 3、即梦）都基于Diffusion（扩散）模型。其核心思想可以类比为「逆向去噪」：模型先学习如何在一张清晰图像上逐步添加噪声直至变成完全的随机噪声（正向扩散过程），然后训练一个神经网络来执行相反操作——从一张纯噪声图像开始，逐步去噪，最终恢复出符合文本描述的清晰图像（反向生成过程）。
产品层面需要理解的关键点是：
Latent Space（潜空间）：模型不是在原始像素空间（一张图动辄几百万像素）直接操作，而是先将图像压缩到一个低维的潜空间中运算，大幅降低计算成本。这意味着Prompt实际上是在「指挥」潜空间中的向量移动方向，最终解码为像素图像。
推理步数（Steps）：从噪声到图像需要迭代多少步去噪。步数越多，生成越精细，但耗时越长；步数过少，图像可能出现模糊或结构错乱。产品设计中需要在质量和速度之间权衡，通常20-50步是常见区间。
Classifier-Free Guidance（CFG Scale）：控制Prompt对生成结果的影响力强度。CFG值越高，生成结果越严格遵循Prompt描述，但可能牺牲图像自然度和多样性；CFG值越低，模型自由度越大，创意更丰富，但可能偏离用户需求。产品化时可以通过提供「创意模式」和「严格模式」让用户自行调节。
种子（Seed）：决定初始噪声的随机数。相同Seed+相同Prompt+相同参数，可以生成几乎一致的图像。这个特性对产品非常重要——它让「复现」和「微调」成为可能。例如，用户生成了一张满意的草图，可以通过固定Seed、微调Prompt来生成系列变体。
ControlNet——精确控制生成结果
Diffusion模型的一个天然局限是可控性弱：同样的Prompt每次输出差异很大，且难以精确控制人物姿态、画面结构、空间深度等。ControlNet通过在Diffusion基础模型上增加一个可训练的「条件控制分支」，实现了对生成过程的精细化约束。
常见的ControlNet控制条件包括：
Canny/Lineart边缘检测：用户提供一张线稿或边缘图，模型在保持结构不变的前提下填充内容和风格。对游戏美术非常重要——美术师可以先画草图，再用AI填充细节和上色。
OpenPose人体姿态：通过骨骼关键点控制人物的姿态和动作，解决文生图中「手画不好」「姿势奇怪」的痛点。
Depth深度图：控制画面中的空间远近关系，保证前景、中景、背景的层次感合理。
Reference/风格参考：提供一张参考图，让生成结果在风格、色调、构图上与参考图保持一致。
产品意义：ControlNet让文生图从「抽卡式创作」升级为「可控式生产」，是AI进入专业工作流的关键技术。面试中可以结合腾讯的游戏资产生成平台场景，讨论如何用ControlNet实现「草图→成品」的 pipeline。
LoRA——低成本风格/角色一致性保持
LoRA（Low-Rank Adaptation）是一种低成本的模型微调技术。传统微调需要更新模型全部参数，成本极高；LoRA只在原模型旁路注入少量可训练参数（通常不到原模型的1%），就能让模型学会特定风格或角色特征。
在游戏和IP场景中，LoRA的核心价值是「角色一致性」：一个游戏可能有几十个角色，每个角色需要在不同场景、不同姿态、不同光照下保持外观一致。用通用模型直接生成，角色长相每次都不一样；用LoRA为每个角色训练一个轻量适配器，就能在生成时调用对应LoRA，确保「每次都是同一个人」。产品设计中需要考虑LoRA的管理（版本、权限、调用规则）、训练数据要求（每个LoRA需要15-30张高质量角色图），以及LoRA与基础模型的兼容性。
主流文生图产品对比（面试谈资）
Midjourney：美学质量最高，风格多样，社区生态强（Prompt分享、风格库）。弱点是可控性差（无ControlNet官方支持）、中文理解弱、商用授权有争议。适合概念设计和灵感发散。
Stable Diffusion（SDXL/FLUX等）：开源生态最丰富，ControlNet、LoRA、ComfyUI工作流等插件齐全，可控性最强，可本地部署。弱点是上手门槛高、出图质量依赖模型和参数调优。适合专业美术 pipeline。
DALL-E 3：与ChatGPT深度集成，语义理解最强（能准确理解复杂长Prompt），文字渲染能力领先。弱点是风格相对单一、可控性不如SD。适合快速原型和营销物料。
即梦（字节）/可灵（快手）：中文理解和中文文字渲染能力强，本土化做得好，与抖音/快手生态联动。适合国内营销场景和短视频配套素材。
3D生成技术（了解概念即可）
NeRF（神经辐射场）：用神经网络表示3D场景，可从2D图像合成新视角。
3D Gaussian Splatting：比NeRF渲染更快的3D表示方法，目前工业界热点。
文生3D/图生3D：输入文本或图片生成3D模型。代表工作如DreamFusion、Magic3D、Meshy。理解其当前局限（生成质量不稳定、拓扑结构需要后处理）很重要。
多模态大模型
能同时理解和生成文本、图像、音频、视频的大模型。GPT-4o、Claude 3.5、Gemini都是多模态模型。产品层面的意义：统一接口处理多种内容类型，降低系统集成复杂度；但也带来更高的计算成本和更复杂的评测挑战。
AI产品评测体系设计
一个完整的AI评测体系应包括：
评测指标分层
系统层：响应时间、吞吐量、可用性、成本。
模型层：准确率、召回率、F1、BLEU/ROUGE（文本）、FID（图像）、用户满意度评分。
产品层：任务完成率、用户留存、NPS、转化率、错误率。
评测方法
人工评测：建立标注团队，制定评分标准和互校机制。适合主观指标（如图像美感）。
自动评测：用脚本批量测试，对比输出与标准答案。适合客观指标（如代码正确性）。
A/B测试：线上真实用户分流对比。
对抗评测：用更难案例测试模型边界，发现弱点。
评测数据集构建
覆盖不同难度、不同场景、不同边缘情况的测试集。需要持续更新，防止模型「过拟合」评测集。你的Agent项目中「案例结构+归一化签名+SQL匹配召回」就是一种结构化的评测案例管理方法。
AI产品合规、兜底与禁止场景
智珑创新JD明确要求「建立AI功能的评测、兜底、人工接管和禁止场景」，这是当前AI产品落地的核心议题：
兜底机制：当AI输出置信度低于阈值、触发敏感词、或用户明确请求人工时，自动转人工接管。设计要点包括兜底触发条件、接管流程、用户体验（避免让用户感到被「踢皮球」）。
禁止场景：明确列出AI不能处理的任务类型（如医疗诊断、法律建议、金融投资）。需要通过系统层面的拦截+用户协议层面的告知双重保障。
内容安全：输入过滤（防止Prompt Injection）、输出审核（防止有害内容生成）、数据隐私（用户数据如何存储和使用）。
可解释性：用户有权了解AI决策依据。尤其在B端场景，需要输出推理过程或引用来源。
